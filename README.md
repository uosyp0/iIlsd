# Legit Assets — Mini App для legit-assets-ecosystem

Цей випуск підготовлений під наданий архів з bot/, manager-bot/ та monobank-relay/. У репозиторії Mini App лише 5 файлів, повний код розпаковується під час збірки. Це Next.js + SQLite, без PostgreSQL.

## Як це працює

Мініапп показує п'ять категорій вашого бота: Steam, Telegram, SMM, проксі, верифікації. Пошук, групи, деталі товару й кнопка «Продовжити в боті». NFT лишається окремою вкладкою з оплатою GRAM через гаманець; реальний NFT-каталог потребує налаштованого MarketApp і чинних параметрів мережі.

Звичайна покупка передається в @LegitAssetsBot у форматі його чинного /start-посилання. Один товар за перехід, щоб автоматична LZT-видача не змішувалася з ручними замовленнями. Бот повторно визначає товар і фінальну суму, показує підтвердження й виконує свій чинний сценарій списання та видачі. Мініапп сам баланс бота не списує. Ціни приходять з того ж _resolve_site_order, який використовує бот, зі знижкою та курсом бота. Відсутнє підключення показується помилкою з повтором, без підміни товарів демо-каталогом.

Профіль читає UAH і GRAM із бота. У цьому боті GRAM зберігається в balance_usd — адаптер враховує це. Історія показує останні 100 manual_orders/webapp_orders тільки поточного Telegram-користувача. Паролі, коди входу й delivered_payload в Mini App не передаються. Для отримання товару відкривайте бота та менеджер-бота у чинному сценарії видачі. Адмін-керування магазином — через вашу панель /admin у боті.

Monobank-relay продовжує працювати з чинною спільною базою. Mini App не приймає банківські вебхуки. Кнопка поповнення відкриває в боті вибір суми або ввід суми через чинний Monobank-сценарій.

## 1. Встановіть сумісний патч бота

Потрібен окремий legit-assets-ecosystem-patch.zip з цієї відповіді. Старі патчі miniapp_bridge.py для попереднього архіву сюди не підходять. Розпакуйте новий патч окремо, виконайте read-only перевірку:

```
python install.py --bot-dir /absolute/path/legit-assets/bot
```

Зупиніть головний бот, виконайте:

```
python install.py --bot-dir /absolute/path/legit-assets/bot --apply --bot-stopped
```

Установник замінює лише сумісний bot.py, додає miniapp_ecosystem.py та робить резервну копію коду. .env, SQLite, менеджер-бот і monobank-relay не змінюються. Не запускайте bot.py з папки патча: решта модулів потрібна з повного архіву. Не запускайте другий Telegram poller.

## 2. Railway для мініаппу

Завантажте 5 файлів у корінь GitHub-репозиторію. На Railway створіть сервіс із цього репозиторію, приєднайте один Volume до /data, згенеруйте публічний домен. Dockerfile і railway.json уже готові.

Variables мініаппу:
- BOT_TOKEN — токен головного @LegitAssetsBot, такий самий як у bot/.env.
- ADMIN_ID — числовий Telegram ID адміністратора.
- BOT_BRIDGE_URL — HTTPS-адреса API бота (може мати префікс шляху).
- BOT_BRIDGE_SECRET — спільний приватний ключ адаптера, мінімум 32 URL-safe символи.
- COMMERCE_MODE=ecosystem — режим цього бота (цей boot.mjs також задає його за замовчуванням).

NEXT_PUBLIC_SITE_URL необов'язковий для стандартного Railway-домену: RAILWAY_PUBLIC_DOMAIN підхоплюється автоматично. Для свого домену вкажіть HTTPS URL. DELIVERY_ENCRYPTION_KEY та внутрішні ключі для нової бази генеруються й зберігаються на Volume. Для наявної бази залиште її старий ключ.

## 3. Зв'язок із чинним сервером бота

Не переносіть три процеси на різні Railway Volumes: їм потрібен той самий файл SQLite. Цей випуск дозволяє залишити всю екосистему бота на її поточному сервері, а Mini App — на Railway. HTTP-адаптер запускається всередині головного бота, окремий Telegram-процес не створюється.

Для генерації парних налаштувань достатньо Node.js, npm install не потрібен:

```
node boot.mjs connect --miniapp=https://YOUR-MINIAPP-DOMAIN --bot=https://YOUR-BOT-API-DOMAIN
```

Скопіюйте connection/miniapp-connection.env у Variables Mini App, а connection/bot-connection.env — у bot/.env чинного бота. Ключ не друкується, файли приватні й не потрапляють у Git. Генератор відмовляється перезаписати існуючі налаштування. Якщо ключ уже існує, використовуйте його і в боті, і в мініаппі. Токен бота та банківські ключі генератор не переносить.

У bot/.env потрібні лише дві нові змінні:
```
BOT_BRIDGE_SECRET=<same-private-key>
MINIAPP_BASE_URL=https://YOUR-MINIAPP-DOMAIN
```
За замовчуванням адаптер слухає 127.0.0.1:8099. Налаштуйте HTTPS reverse proxy до цього порту. Приклад для вже налаштованого HTTPS virtual host Nginx:
```
location /miniapp-api/ {
    proxy_pass http://127.0.0.1:8099/;
    proxy_set_header Host $host;
    proxy_connect_timeout 5s;
    proxy_read_timeout 30s;
}
```
Для такого шляху задайте BOT_BRIDGE_URL=https://YOUR-BOT-DOMAIN/miniapp-api (вручну в Railway Variables). Адаптер не відкриває базу через мережу. /health повертає тільки {ok:true}; /balance, /catalog, /orders потребують Bearer-ключа. Ключ зберігається на серверах і не передається в браузер.

Після встановлення й налаштування перезапустіть ОДИН головний бот. Він додасть кнопку меню «Магазин» із MINIAPP_BASE_URL. За потреби цю ж адресу можна вказати у BotFather → Bot Settings → Menu Button. Адреса Mini App і адреса API бота — різні налаштування.

## Перевірка

1. Відкрийте Mini App через @LegitAssetsBot, оберіть мову та пройдіть вступ.
2. Перевірте 5 категорій, пошук, групи та суму вибраного товару.
3. «Продовжити в боті» має показати підтвердження чинного бота; сам перехід нічого не купує.
4. Перевірте, що UAH/GRAM в профілі збігаються з ботом та історія показує лише ваші замовлення.
5. «Поповнити» відкриває вибір/ввід суми в боті. Реальну банківську операцію перевіряйте окремо на своєму сервері.

Локальний код:
```
node boot.mjs unpack
node boot.mjs install
node boot.mjs run typecheck
node boot.mjs run test
node boot.mjs build
node boot.mjs dev
```
Для змін згенерованих маршрутів/тестів: у .runtime виконайте npm run source:pack, потім у корені node boot.mjs pack. Обидві операції зберігають повний код.

Зберігайте фінансову історію та спільну базу бота постійно. У Mini App тимчасові кошики/обране очищуються за чинним TTL 72 години; фінансові записи не очищуються через 3 дні.

## Локальні перевірки цього випуску
109 Node-тестів, 12 Python-тестів (включно з реальною HTTPS-взаємодією двох локальних процесів), TypeScript і production build пройшли. Браузерна перевірка магазину, SMM, проксі, NFT, історії та профілю — без JS-помилок, без горизонтального overflow на перевірених 320/430 px; пошук, групи й передача посилання боту перевірені на тестових даних. Реальні Telegram-покупки, LZT-закупівлі та банківські перекази не виконувалися. Публічні сервери не змінювалися.
